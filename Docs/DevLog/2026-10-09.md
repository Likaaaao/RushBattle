## 卡住的

五个坑，**共同点是不报错、静默失败**。

### ① `Give Ability And Activate Once` 拒绝 `Local Only` 的技能

`AbilitySystemComponent_Abilities.cpp:321`

```cpp
if (InstancingPolicy == NonInstanced || NetExecutionPolicy == LocalOnly)
    return FGameplayAbilitySpecHandle();   // 空 Handle
```

只打 `LogAbilitySystem` 的 Error，蓝图侧只看到 `Try Activate Ability` 返回 false。
**改用 `Give Ability` + `Try Activate Ability` 两步（本来就是常规做法）。**

### ② 冷却 GE 不授予 Tag = 冷却完全无效

`GameplayAbility.cpp:1089` 有对应 Warning；判定用 `GetGrantedTags()`。

**UE 5.3 之后 GE 的标签配置搬到了 `Gameplay Effect Components`**，老教程里的 `Granted Tags` 字段已不存在 —— 找不到不是漏看。
→ 加 `Target Tags Gameplay Effect Component`，填 `Cooldown.Fire`。

### ③ `SetByCaller` 有两张表，用错节点静默跳过

`FGameplayEffectSpec` 上 `SetByCallerNameMagnitudes`（FName）和 `SetByCallerTagMagnitudes`（Tag）是两张独立表。

GE 的查找是 if-else（`GameplayEffect.cpp:1221`）：`DataTag` 有效 → 查 Tag 表；否则查 FName 表。
而 `DataName` 是 `VisibleDefaultsOnly`，**编辑器里改不了** → 只能走 Tag 表。

蓝图节点 `Assign Set By Caller Magnitude`（引脚 **`Data Name`**）写的是 FName 表 → **没人读**。
→ 必须用 **`Assign Tag Set By Caller Magnitude`**（引脚 **`Data Tag`**）。

### ④ 「我正在换弹」是状态，不是冷却

| 要表达 | 用什么 |
|---|---|
| 冷却（要倒计时） | GE + `Target Tags Gameplay Effect Component` |
| 当前状态（激活期间挂 / 结束自动摘） | **`Activation Owned Tags`** |

`InstancedPerExecution` 下每次激活都是新实例，"技能已激活"挡不住重复激活 → 只能用 Tag。

### ⑤ `Wait Delay` 而不是 `Delay`

`Delay` 不能被打断：技能被取消后回调照样执行（切枪打断换弹 → 2 秒后弹药自己去补）。
`AbilityTask_WaitDelay` 跟随技能生命周期，自动取消。

## 关键决定

| 决定 | 原因 |
|---|---|
| **GA 只做调度，真实逻辑留在武器** | 换把枪就变的数据不属于 GA |
| **射速用冷却 GE，不用 Timer** | 删掉手写 Timer；改射速只改一个数字 |
| **状态用 `Activation Owned Tags`，冷却用 GE** | 一个要自动挂摘，一个要倒计时 |
| **死亡用 `Wait for Attribute Changed`，不用 C++ 的 `PostGameplayEffectExecute`** | 避免 AttributeSet 耦合玩家 / 敌人两个类型 |
| **敌人攻击不建 GA，直接在 Task 里施加 GE** | 行为树已经管前摇和冷却 |
| **`Owner Actor` 变量不用，改用 `Get Owner`** | 变量要有人负责 SET，迟早会忘；`Get Owner` 引擎保证 |
