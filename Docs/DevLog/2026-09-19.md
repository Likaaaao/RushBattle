## 卡住的 / 搞不懂的

今天踩的坑比前几天加起来还多，而且**七成是"静默失败"**。

### ① `BP_M1911` 里网格转不了 —— 两个原因叠加

在子类里改 `weapon` 网格组件的变换，失败。后来发现是**两个独立的原因**：

| 原因 | 提示信息 |
|---|---|
| **组件从父类继承** | "它从父类继承而来，所以不能在此处编辑它的属性" |
| **移动性 = 静态** | 位置/旋转必须可移动；Static 组件会被引擎锁住 |

**判定方法**：`变换` 分组里如果**只有"缩放"一行**，说明这个组件是**根组件**——根组件的位姿由关卡摆放决定，蓝图里不给编辑。

**解法**：加一个 `场景组件` 当新的根，把网格降为子级。**这本来就是 UE 的标准做法**，根组件是纯坐标系，模型是它的子级。

> 教训：**"改不了"往往不止一个原因。** 解决掉一个之后还不行，不要以为是自己操作错——继续找第二个。

### ② `有效索引` 检查错了对象 —— 第一次切换永远失败

防护子句我写的是"检查目标索引"，实际写成了：

```
IS VALID INDEX(Weapons, CurrentWeaponIndex)     ❌
```

而 `CurrentWeaponIndex` 的初始值是 **`-1`**（故意的，为了让第一次切换不被"索引相同"那条拦住）。

结果：`IsValidIndex(Weapons, -1)` 恒为假 → **第一次 `SwitchWeapon(0)` 直接被拦死**。

**正确**：检查 `Index`（这次请求要切过去的位置）。

> 教训：**写防护子句时，每一条都要问"它在防什么"。**
> 前两条检查的是"这次请求合不合法"，只有最后一条才需要拿"当前状态"来比。

### ③ 分支没接全 —— 第一次能切，后续没反应

`SwitchWeapon` 里有两段：

```
旧武器清理（分支2.真 的路径）
新武器装备（两条路都要走）
```

**"清理"那段的末尾没有汇合到"装备"那段的入口。**

症状很典型：

| 调用 | 走哪条路 | 结果 |
|---|---|---|
| 第一次（旧武器为空） | `分支2.假` | ✅ 直接到装备段，正常 |
| 后续（按 1/2/Q） | `分支2.真` | ❌ 清理完就结束了，新武器从没被装备 |

> **蓝图里"汇合"靠的是"多条执行线接到同一个节点"。** 一个执行输入引脚可以接多条线。
>
> **教训**：当一条执行链里出现"两条路都要汇合到同一个后续"，通常意味着**该抽函数了**。
> 抽出去之后分支只在函数内部，两条路都直接到出口，主流程变成直线，天然没有汇合问题。

### ⑤ 切枪后 HUD 不刷新 —— 又要手动刷一次

现象：**开火后 UI 才刷新**。

**能从现象反推出诊断**：

| 现象 | 说明 |
|---|---|
| 开火后能刷新 | 绑定 ✓、`HandleAmmoChanged` ✓、`SetAmmo` ✓ 全是好的 |
| 切枪后不刷新 | **只是末尾那句"主动刷新"没生效** |

**根因**：绑定事件**不会立即触发一次**。切枪时没人主动刷，要等下一次广播（也就是开火）才更新。

> **这是第二次踩同一个原理**（第一次是 `SpawnWeapon` 里的初始化）。
> **凡是"切换了当前对象"的地方，都必须手动刷新一次。**

### ⑦ `Get` 节点搜不到 —— 引擎故意不让搜

想搜数组的"按索引取值"节点，中文英文都搜不到。

查引擎源码发现：

```cpp
// KismetArrayLibrary.h:184
meta=(BlueprintInternalUseOnly = "true", DisplayName = "Get", ...)
```

**`BlueprintInternalUseOnly` 表示这个节点不出现在搜索菜单里，只能从数组引脚拖出来。**

> 通用经验：**UE 里所有容器操作，最省事的做法都是从容器引脚拖出来**，而不是右键搜索。
> 拖出来时引擎会按引脚类型自动过滤，比搜索准确。

## 关键决定

| 决定 | 原因 | 放弃了什么 |
|---|---|---|
| **武器类只有一个 `BP_GunBase`**，删掉 `BP_M1911` / `BP_AK47` | 子类只能表达"模型不同"，却带来"继承组件改不了"和"每加一把枪建一个类"两个负担 | 需要把模型引用放进数据资产 |
| **切枪用"全部生成 + 可见性切换"** | 不需要 `SpawnActor`；弹药状态天然按武器各自保存（每把枪是独立 Actor） | 开局就把所有武器生成出来 |
| **武器默认关闭碰撞** | `设置Actor隐藏` 只影响渲染，**不影响碰撞**——藏在手里的枪照样会挡子弹 | 无 |
| **换弹用定时器句柄而不是 `Delay`** | `Delay` 无法取消；换弹中切枪时，回调会把**新枪**的弹药改乱 | 多存一个句柄变量 |
| **`CurrentWeaponIndex` 初始值 `-1`** | 表示"还没装备任何武器"，让第一次切换能通过"不是同一把"的检查 | 需要保证后续所有读取都先判有效 |

## **"静默失败"有四类**

这个提炼比具体修好某个 bug 更有价值。**它们全都不报错、不中断，只是行为不对：**

| # | 类型 | 表现 | 怎么防 |
|---|---|---|---|
| 1 | **`Cast` 失败** | 后面整条链不执行 | 接 `Cast Failed` 打印 |
| 2 | **派发器参数没接** | 广播出去的是 `null` / `0` | 接收方打印参数的显示名 |
| 3 | **空引用读取** | **只有 Output Log 里一行红字**，游戏照跑 | **出问题先看日志，别只看画面** |
| 4 | **绑定 ≠ 立即执行** | 数据是对的，但 UI 要等下一次广播 | "切换当前对象"后手动刷一次 |

**第 3 条是今天新认识的**——以前只看画面判断，今天才知道**日志里一直在报错**。
