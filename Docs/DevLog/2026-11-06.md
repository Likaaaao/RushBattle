## 工作

### 1. 属性集拆分：`UMyAttributeSet` + `UResourceSet`

**问题**：15 个属性里 11 个只有玩家用（Ammo / Energy / Money / 资源点 / 倍率），敌人身上带一堆死字段。

**方案**：拆成两个 AttributeSet，但**不新建 Character 子类**。

```cpp
UMyAttributeSet（玩家 + 敌人共用，C++ CreateDefaultSubobject 自动注册）
    Health / MaxHealth / Speed / MaxSpeed

UResourceSet（只有玩家，BP_Player 里 Init Stats 创建，敌人不调）
    Ammo / MaxAmmo / Energy / MaxEnergy / Money
    6 个资源点
    5 个倍率（11 月新增）
```

**为什么不用 Character 子类**：蓝图不能给 Actor 加非组件子对象。但 **`Init Stats` 可以从蓝图调用**（内部 `NewObject + AddSpawnedAttribute`），一行解决。

**踩的坑**：
- `ATTRIBUTE_ACCESSORS_BASIC` 的第一个参数是**属性所属的类**。从旧头文件复制过来只改了属性名、没改类名 → `C2039: 不是 UMyAttributeSet 的成员`
- `ResourceSet.cpp` 里保留了 `DOREPLIFETIME` → 属性没标 `Replicated` → 编译报 `UnrealNetwork.h` 的 Fatal 模板错误。**单机项目直接删掉 `GetLifetimeReplicatedProps`**
- 三个 DA 迁移：`BP_WeaponData` 改父类后，**蓝图里和 C++ 同名的变量会遮蔽父类字段** → 必须删掉蓝图里的重复变量

### 2. 资源点机制（6.4b）

**设计从"击杀直接加资源"改成"击杀得点数，按键兑换"。**

好处：资源满时击杀不再浪费；把"什么时候换"变成玩家的主动决策。

**实现**：
```
击杀 → OnKilledEnemy → Switch on EnemyTag → GE_Add_*Point（+1 点数）
按键 → 查点数 ≥ 1 → GE_Add_*Point（传 -1）→ GE_Heal / RefillAmmo / RefillEnergy
```

**关键：复用同一个加法 GE 传负数来扣点**，不需要新的"扣点 GE"。

### 3. 敌人攻击走 GA（6.5）

**结构**：
```
BTT_Attack / BTT_RangedAttack
    → BP_EnemyBase.Attack(Target) -> bool
        → 查冷却 Tag（拿不到 SendGameplayEvent 的返回值，只能自己查）
        → 存 CurrentAttackTarget
        → Send Gameplay Event to Actor(self, AttackEventTag)
            → GA_Enemy_GunFire / GA_Enemy_MeleeAttack
```

**为什么 `Attack()` 要返回 bool**：`SendGameplayEventToActor` 是 `void`，拿不到"有没有 GA 响应"。查冷却 Tag 是唯一能让行为树知道成败的办法。

**坑：蓝图 GA 拿不到 payload** —— `Event Activate Ability` 是无参版本（`K2_ActivateAbility`）。被 GameplayEvent 触发时必须重写 **`Event Activate Ability From Event`**（`K2_ActivateAbilityFromEvent`），节点上才有 `Event Data` 引脚。

### 4. 近战攻击（6.6）

`GA_Enemy_MeleeAttack`：前摇 0.4s → `BP_EnemyBase.PerformMeleeAttack(Target)` → 距离/球形检测 → `DealDamageTo`。

**和远程共用 `GE_EnemyAttackCooldown`**（同一个 `Cooldown.EnemyAttack` Tag）。

### 5. 敌人持续转向：`BTS_FaceToTarget`

**原来的问题**：只在攻击序列里 `Rotate to face BB entry` 一次 → 转向"一顿一顿"。

**试过但不行的**：
- `Simple Parallel` —— 主/背景引脚**只接受 Task，不接受 Selector/Sequence**，报 `仅允许任务节点`
- 背景放 Sequence —— 同样被拒

**最终方案**：BT Service，Interval 0.05s，在 `Event Receive Tick` 里 `RInterp To` + `Set Actor Rotation`。

**注意**：`Owner Actor` 参数是 **AIController**，不是 Pawn，要 `Get Controlled Pawn` 再 Cast。

### 6. `AWeaponBase`：武器持有能力

```
TArray<TSubclassOf<UGameplayAbility>> WeaponAbilities
TArray<FGameplayAbilitySpecHandle>    GrantedAbilityHandles
```

`GrantAbilitiesToOwner()` 里**去重**（ASC 上已有同类 GA 就跳过），否则同一把 GA 会被授予多次。

**换武器顺序必须是**：旧武器 Remove → 新武器 Grant。反过来的话，去重逻辑会让第二把武器不记录 handle，第一把移除时把共用能力一起撤掉。

**`InitWeapon` 改成显式调用**：原来在 `BeginPlay` 里读 `WeaponData`，但 `SpawnActor` 返回时 `BeginPlay` 已经跑完了，所以数据还没设 → 原来靠 "Delay Until Next Frame" 补。

改成"数据设完之后由生成方调 `InitWeapon`"，`BeginPlay` 只在数据已存在时兜底。

### 7. 三层伤害数值模型

```
第一层  武器基础值     DA_Gun_*（BaseDamage / BaseCritChance / BaseCritMultiplier）
第二层  玩家倍率       UResourceSet（5 个属性，Infinite GE 修改）
第三层  全局倍率       公式里先写死 ×1.0，以后接模式/角色配置
```

**加算 vs 乘算**：
```
暴击率    = Clamp(基础 + 层2 + 层3, 0, 1)      ← 加算
暴击倍率  = 基础 + 层2 + 层3                    ← 加算
伤害      = 基础 × 层2倍率 × 层3倍率 × 暴击倍率  ← 层间乘算
```

**拆成两个函数**：
- `GetFinalStats()` —— 只算数值，不判暴击（UI 显示 DPS / 暴击率时复用）
- `CalculateFinalDamage()` —— 调 `GetFinalStats` + 判暴击

**踩的坑**：暴击倍率引脚接错成了暴击率，暴击时伤害反而只有原来的 10%。因为暴击率只有 10%，很难一眼发现。

### 8. 性能观测：PIE 里测 Slate 是假的

**这是这个月最有价值的一条。**

```
PIE 里：      Slate 6.21 ms，Elements 568，SWidgetPaint 1580
Standalone：  Slate 0.35 ms，Elements  12，SWidgetPaint   29
```

**差 18 倍。** PIE 里测到的"UI 开销"绝大部分是 Details 面板、Content Browser、工具栏、还有 `stat` 面板自己。

**所以前面为了"优化血条 Slate"做的所有分析全部作废。**

**一个有用的副产品**：`stat slate` 里出现 `SDetailsView [PropertyEditor.cpp]` 说明编辑器面板被算进来了 —— 看到这行就知道数据不可信。

**其它几条**：
- `stat unit` 里 `Frame ≈ 三者中最大的那个`；`Game` / `Draw` / `GPU` 是并行线程，不能相加
- `Inclusive` 含子项，`Exclusive` 只算自己。挖到 `Exclusive ≈ Inclusive` 才是叶子节点
- `-game` 模式必须 100% 屏幕百分比才有意义（原来是 50%）

**基线（Standalone，1280×720，100%）**：

| 场景 | Frame | Game | Draw | GPU | Draws |
|---|---|---|---|---|---|
| 空场景 | 8.41 | 4.97 | 8.40 | — | 276 |
| 48 敌人 | 9.07 | 6.72 | 9.08 | 6.51 | 499 |

**Gameplay 每敌人 0.036 ms —— 非常健康。瓶颈在 Draw 线程。**

**发现的两个渲染开销**：
- 光追：`Ray tracing dynamic update primitives = 75,081`，每帧重建，和画多少东西无关。关掉后 Draw 8.97 → 7.02
- GPU 7.26 ms 偏高，怀疑体积云（截图背景有云），未验证

### 9. 饰品系统（6.7）

**设计从"三选一"改成"掉在地上，走过去捡"。**

```
UTrinketDataAsset          一条饰品（DisplayName / Rarity / Weight / EffectToApply）
UTrinketPoolDataAsset      池子（TArray<TObjectPtr<UTrinketDataAsset>>）
UTrinketComponent          6 个槽，装/换/撤/清空
```

**同种饰品可以占多个槽，不设叠加上限**（唯一限制是 6 个槽）。

**最大的坑：GE 的 `Duration Policy` 必须是 `Infinite`。**

```
Instant GE 施加后：
    ① 立刻改属性 ✅
    ② 不产生 ActiveGameplayEffect
    ③ ApplyGameplayEffectSpecToSelf 返回【无效 handle】

结果：属性变了，但 ClearAllTrinkets 撤不掉 → "清空没效果"
判断信号：日志里 handle valid=NO，但属性确实变了
```

**另一个坑：`TrinketPool` 写成 `TArray<TSubclassOf<...>>` 导致数据资产里"选不了"**

```
TSubclassOf    数据资产选择器里只列"类"
TObjectPtr     只列"实例"

饰品池装的是"已存在的资产实例" → 必须 TObjectPtr
```

**还有一个坑：用「蓝图类」当数据资产**

```
内容浏览器 → 蓝图类 → 父类选 TrinketPoolDataAsset
    → 得到的是一个「类」，不是「实例」
    → 不能赋给 TObjectPtr 字段 → 选择器显示"无结果"

正确：右键 → 杂项 → 数据资产 → 选类
```

### 10. `Tinket` → `Trinket` 改名

**26 处拼写错误，5 个文件，包括类名 `UTinketDataAsset`。**

**因为改的是类名（不是文件名），蓝图父类会断。用 `CoreRedirects`：**

```ini
[CoreRedirects]
+ClassRedirects=(OldName="/Script/RushBattle.TinketDataAsset",NewName="/Script/RushBattle.TrinketDataAsset")
+EnumRedirects=(OldName="/Script/RushBattle.ETinketType",NewName="/Script/RushBattle.ETrinketType")
```

**顺序必须是**：

```
① 先写 CoreRedirects（Config/DefaultEngine.ini）
② 关编辑器
③ 全局替换代码 + 重命名文件
④ 重新生成项目文件 → Rebuild
⑤ 打开编辑器（这时读 CoreRedirects，蓝图父类自动迁移）
```

**打开后第一时间检查三处，任何一处是 `None` 就立刻不保存关掉：**
`DA_Trinket_*` 的父类、`DA_TrinketPool` 的数组内容、`BP_Player` 的字段。

## 踩的坑汇总

| 坑 | 症状 | 根因 |
|---|---|---|
| `ATTRIBUTE_ACCESSORS_BASIC` 参数错 | `C2039: 不是 X 的成员` | 第一个参数是"属性所属的类" |
| `DOREPLIFETIME` + 非复制属性 | `UnrealNetwork.h` 模板错误 | 单机项目删掉 `GetLifetimeReplicatedProps` |
| `if` 少写花括号 | 报"未声明的标识符"（在下一行） | 那行成了 `if` 的 body，作用域被限制 |
| `UE_LOG` 里用中文 | `C2001: 常量中有换行符` | UTF-8 无 BOM，MSVC 按 GBK 解析，中文字节里的 `0x5C` 被当转义符 |
| 事件触发 GA 拿不到 payload | Target 一直是空 | 用了无参的 `Event Activate Ability` |
| `SendGameplayEvent` 无返回值 | 不知道成没成功 | 自己查冷却 Tag |
| `Simple Parallel` 接组合节点 | `仅允许任务节点` | 两个子引脚只接受 Task |
| 暴击时伤害变小 | 数字对不上 | 暴击倍率引脚接到了暴击率 |
| `Instant` GE | `handle valid=NO`，撤不掉 | Instant 不产生 ActiveGameplayEffect |
| `TSubclassOf` 用错地方 | 资产选择器"无结果" | 要实例用了"类"类型 |
| 用蓝图类当数据资产 | 同上 | 建了蓝图类而不是数据资产实例 |
| PIE 里测 Slate | 数据大 18 倍 | 编辑器 UI 也算在里面 |
| 改 C++ 类名 | 蓝图父类变 None | 必须配 CoreRedirects |

## 反思

**1. 测量前先问"这个数字里混了什么"。**

PIE 里那 6 毫秒的 Slate，折腾了好几轮才想到是编辑器 UI。如果第一天就用 Standalone 测，能省掉整个"优化血条"的错误方向。

**2. "暂时用 Delay 绕过"的补丁迟早要还。**

`InitWeapon` 原来靠"等一帧"，能跑但很脆（帧率、加载、对象池都会让它失效）。改成显式调用后逻辑变直白，而且顺手解决了"数据传不进去"。

**3. 属性"能加不能撤"是 GAS 里最容易忽略的语义差异。**

`Instant` / `Has Duration` / `Infinite` 三种 Duration Policy 决定了有没有 handle、能不能撤、能不能叠层。选错了不会报错，只会"表现不对"。

**4. 蓝图选择器"选不了"通常不是 bug，是类型不匹配。**

`TSubclassOf` vs `TObjectPtr`、蓝图类 vs 数据资产实例 —— 这两种情况都表现为"下拉框里什么都没有"，但原因完全不同。
