## 工作

### 一、镜头晃动（Camera Bob）修好了：`BobTime` 根本没累积

**症状**：`UpdateCamera` 里 `BobTime` 一直是 `0.15`，一点不涨，镜头完全不晃。

**原以为**：`SIN`（正弦）连线接错了，或者幅度太小看不出来。把 `BobAmplitudeY/Z` 临时调到 `20 / 30` 还是毫无反应 → 排除「幅度太小」。

**实际**：`BobTime` 被放在**函数的局部变量（Local Variables）**里。

| | 生命周期 | 初值 |
|---|---|---|
| 局部变量（Local） | **每次调用重新创建，函数返回就销毁** | 每次都是默认值 |
| 成员变量（Member） | 跟着 Actor 实例活 | 只在生成时初始化一次 |

所以每帧算出来的 `BobTime + DeltaTime`，写进的是一个**当帧就死掉的变量**，下一帧又从 `0.15` 开始。

**规则**：凡是「跨帧累积」的量——相位、计时器、累积后坐力、当前插值状态——**一律必须是成员变量**。

**待办**：`BobAmplitudeY = 20` / `BobAmplitudeZ = 30` 是排查时临时调大的，要改回 `2.0` / `3.5`。

### 三、摄像机 Roll 倾斜（左右倾斜）——今天只出了方案，没实施

**需求**：冲刺横移时镜头朝移动方向倾斜。

**撞到的墙**：摄像机勾了 `Use Pawn Control Rotation`（使用Pawn控制旋转）之后，**每帧把自己的世界旋转覆盖成 Pawn 的视角旋转**：

`Engine\Source\Runtime\Engine\Private\Camera\CameraComponent.cpp:425`

```cpp
if (bUsePawnControlRotation)
{
    const FRotator PawnViewRotation = OwningPawn->GetViewRotation();
    if (!PawnViewRotation.Equals(GetComponentRotation()))
    {
        SetWorldRotation(PawnViewRotation);      // ← 每帧强行覆盖
    }
}
```

所以在摄像机上 `Set Relative Rotation`（设置相对旋转）写 Roll 是**无效的**，下一帧就被冲掉。这不是连线问题，是设计如此。

**两条路**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 接管旋转**（选它） | 取消勾选 `Use Pawn Control Rotation`，每帧自己写 `Make Rotator`（构造旋转体）：Pitch / Yaw 取自 `Get Control Rotation`（获取控制旋转），Roll 换成算出来的倾斜角 | 摄像机不再自动跟鼠标，Tick 变成硬依赖 |
| B. 加弹簧臂 | 弹簧臂勾 `Use Pawn Control Rotation`，摄像机作其子级且不勾 | 多一个组件，`CameraBaseY/Z` 的坐标系要重算 |

**选 A 的理由**：位置那一路（`BobTime` / `CameraBaseY/Z`）一行都不用动，只把旋转这一路接管过来。

**执行顺序（重要）**：必须**先**连好旋转写入并编译通过，**最后**才取消勾选。反过来的话，中间那段时间两种驱动方式都失效，视角会完全锁死，很容易误判成节点写错了。

## 卡住的 / 搞不懂的

### ① `My Blueprint` 面板就是不能多选变量，`Ctrl` 点不中第二个

**原以为是**：我操作不对，或者 UE 5.7 改了什么。

**实际是**：这个面板**在引擎源码层面就是单选的**：

`Engine\Source\Editor\GraphEditor\Private\SGraphActionMenu.cpp:379`

```cpp
.SelectionMode(ESelectionMode::Single)
```

`My Blueprint`（我的蓝图）那一列（变量 / 函数 / 事件 / 宏）用的就是这个 `SGraphActionMenu`（图表动作菜单）控件，所以 `Ctrl`（Ctrl）/ `Shift`（Shift）多选**根本不存在**，跟版本无关，一直如此。

**连带结论**：变量**不能批量改 `Category`（分类）**，只能一个个设。想绕过去写脚本也不行——把 `BlueprintEditorLibrary.h` 翻完了，`SetBlueprintVariable*` 系列只有三个：

```
SetBlueprintVariableExposeOnSpawn      （出生时暴露）
SetBlueprintVariableExposeToCinematics （暴露给过场）
SetBlueprintVariableInstanceEditable   （实例可编辑）
```

**没有 `SetBlueprintVariableCategory`。**

**唯一能省事的地方**：重命名。选中变量按 `F2`，引用会自动跟着改，不用手动找引用点。

### ② 分类下拉框里只有「默认」和「角色」，以为建不了新分类

**原以为是**：只能从下拉里挑，所以自定义分类没戏。

**实际是**：那个框是**可编辑文本框 + 下拉**，下拉里只是「已有分类的历史记录」。点进文字 → 全选删掉 → 打新名字 → 回车，就建好了，下次其它变量的下拉里就有它。

层级用 `|`（竖线）分隔，比如 `Camera|Bob`。引擎就是这么切分的：

`Engine\Source\Editor\Kismet\Private\SMyBlueprint.cpp:244`

```cpp
int32 RootCategoryDelim = Category.Find(TEXT("|"));
```

## 关键决定

| 决定 | 原因 | 放弃了什么 |
|---|---|---|
| **倾斜走「接管旋转」（方案 A）** | `Use Pawn Control Rotation` 每帧覆盖组件旋转，不接管就写不进去 | 摄像机不再自动跟鼠标，Tick 成为硬依赖 |
| **插值幅度用 `FInterp To`，不用 `Lerp`** | `FInterp To` 内部带 `DeltaTime`，帧率无关；`Lerp`（线性插值）的混合比例不随帧率变，帧率一动手感就变 | 无 |
| **一次只写一个镜头通道** | FOV / 相对位置 / 旋转各自只有一个 `Set` 点，所有偏移先求和再写。多个写点会互相覆盖，插值状态还会打架 | `UpdateCamera` 被拆成三个函数 |
| **跨帧累积量一律用成员变量** | `BobTime` 放局部变量导致每帧归零（见上） | `My Blueprint` 变量表变长，只能靠 `Category` 压 |
| **变量先按 `Category` 分组，暂不抽组件** | 手感参数还在天天改，现在抽会边抽边改 | 面板里变量还是多 |
| **正弦类连续波形只插值幅度，不插值位置** | 位置本身已经在随时间变，再插值等于把波形拖慢并衰减 | 无（滑铲那种「台阶式」目标才插值位置） |
