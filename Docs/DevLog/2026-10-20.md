## 卡住的

### ① 改 C++ 类名会摧毁所有继承它的蓝图

蓝图的父类存的是一个**字符串**：

```
/Script/RushBattle.RushBattleCharacter
```

`ARushBattleCharacter` 不是文件，是 DLL 反射表里的一个 `UClass`，**只有名字**。

改源文本 + 改文件名 + 重编译，在 UE 眼里 = **删除一个类 + 新建一个类**。
它不知道两者是同一个东西。

```
改类名
  → 蓝图打开时查不到父类
  → ParentClass = nullptr（蓝图进入非法状态）
  → 【我保存了它】
  → 父类被写成 null，依赖父类的变量一起丢失
  → 资产永久损坏
```

丢失的变量：`Weapons` / `CurrentWeapon` / `CurrentWeaponIndex` / `NewWeapon` / `NewWeaponData`。
连带 `GA_Fire` / `GA_Reload` 里的 `Cast To BP_Player` 也失效（报「坏的类型转换节点」）。

**为什么事后救不回来**：

| 办法 | 为什么无效 |
|---|---|
| `CoreRedirects` | 重定向的是「旧名字引用」；资产里存的是 **null**，没有名字可重定向 |
| 类名改回原名 | 同上 —— 字段是空的，不是指向一个不存在的类 |

**唯一恢复方式**：`Saved/Autosaves/` 里父类还正确的版本。

### ② `CoreRedirects` 只在编辑器启动时读一次

- 只放 `Config/DefaultEngine.ini`
- 加完**必须重启编辑器**
- **必须在改成新名后第一次启动之前就存在** —— 事后加已经晚了

### ③ `SetByCaller` 的 Modifier Op 容易漏

`GE_InitStats` 两条 Modifier 一开始都是「添加（基础）」= Additive，会在初始值上累加。
必须改成「重载」= Override。

同一份 GE 里：`MaxHealth` 那条要排在第 1 位，`Health` 排第 2 ——
否则 `PreAttributeChange` 会用**旧的** MaxHealth 把 Health 夹住。

### ④ 全局文本替换改 C++ 类名会误伤模块名

`RushBattle` → `My` 的替换把 `RushBattle.Build.cs` 里的 `class RushBattle` 和
`IMPLEMENT_PRIMARY_GAME_MODULE(..., RushBattle, "RushBattle")` 一起改了 → 模块找不到。

**模块名四处必须一致**：`.uproject` / `Source/<名字>/` 目录 / `Build.cs` 的 class / `IMPLEMENT_PRIMARY_GAME_MODULE`。
**类名和模块名是两回事，替换时要用更长的字符串（`RushBattleCharacter`）定位。**

## 教训

> **蓝图的父类一旦显示 `None`，立刻关掉，绝对不要保存。**
> **保存 = 把 null 写进磁盘 = 永久损坏。不保存就一定能恢复。**

改 C++ 类名的正确顺序（如果非要改）：

```
① 关编辑器
② git commit 一次，留退路
③ 在 Config/DefaultEngine.ini 加 CoreRedirects（旧名 → 新名）
④ 再改代码 / 改文件名 / 编译
⑤ 启动编辑器（redirect 在此时生效）
⑥ 立刻检查所有继承它的蓝图父类
⑦ 父类正常 → 继续；父类 None → 关编辑器，回滚 git
```

**最安全的做法：不改，新建一个类，蓝图手动重设父类。**
