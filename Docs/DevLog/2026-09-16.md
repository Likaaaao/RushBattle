## 今天做了什么

今天没有写游戏逻辑，做的是**工程地基**的两件事：梳理结构、建立版本控制。

### 1. 梳理了工程结构

把整个工程的目录和体积量了一遍。关键结论：

- 顶层只有 `Content/` 和 `Config/` 是真正需要保护的，其余（`Intermediate/`、
  `DerivedDataCache/`、`Saved/`）都能由引擎重建。
- `Saved/` 占了 115 MB，其中 **107 MB 是 `webcache_6613`**——编辑器内置浏览器的
  缓存，纯垃圾，删了不影响任何东西。
- 没有 `Source/`、`Binaries/`、`Build/`，确认是纯蓝图工程。
- **没有 `.git`**，也就是完全没有版本控制。这是今天要解决的头号问题。

### 2. 建立了版本控制

Git + Git LFS，仓库私有，配了开发日志体系（就是你现在看的这个目录）。

## 结构体检发现的问题

按严重度排，前两条现在不影响功能，第三条是真问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | `UI/` 藏在 `Player/System/` 下 | 低 | UI 不是玩家的附属品。后面敌人血条、波次提示、掉落提示都要用 UI，放在 `Player/` 下将来复用会别扭 |

| 4 | 没有版本控制 | **高** | 已解决 |

另外记一笔：`DefaultEngine.ini` 第 36-37 行有一行重复的 `DefaultGraphicsRHI`，
无害，是编辑器写配置时的常见冗余，不用管。

## 关键决定

| 决定 | 原因 | 放弃了什么 |
|---|---|---|
| 仓库设为 **私有** | 开发期；仓库里的 Fab/商城资产可能涉及再分发授权问题 | 暂时不能被别人直接看到（以后想展示可一键转公开） |
| `Free_Sounds_Pack` **不纳入版本控制** | 65 MB，占 Content 的 99%，且在 `Content/Code` 下搜不到任何引用（**0 次引用**），是纯占位 | 换机器 clone 后需要重新从 Fab 下载该包 |
| 二进制资产走 **Git LFS** | UE 的 `.uasset`/`.umap` 是二进制，git 无法增量压缩，每改一次存一份完整副本 | 别人 clone 前必须先装 git-lfs |
| 用 `Docs/DevLog/` 按日期记录 | 服务于清单第 11 项：面试要讲「发现→定位→解决→数据对比」，靠当场记录 | 每天要花 5 分钟 |
