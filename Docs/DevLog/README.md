## 怎么写

### 命名

```
YYYY-MM-DD.md        例：2026-09-16.md
```

一天只写一个文件。**同一天继续写，就往同一个文件里追加**，不要新建 `2026-09-16-2.md`。

### 新建一篇

复制 `_TEMPLATE.md`，改名为今天的日期，填内容，然后**回到上面这张索引表加一行**。

### 什么时候写

- 收工前花 5 分钟写。**不要攒**，攒了就一定不会写。
- 卡住超过 30 分钟也要记一笔——「我当时以为是什么、实际是什么」比「最后怎么解决的」更有价值。
- 做完任何优化，必须当次记录数据。隔天再补的数据是编的，不是测的。

### 为什么值得写

这份日志有三个用途，按重要性排序：

1. **给未来的自己看。** 三个月后你会完全忘记今天为什么这么设计。
2. **性能优化的证据链。** 面试时能讲出「发现 → 定位 → 解决 → 数据对比」的完整故事，全部靠这里的当场记录。
3. **简历素材。** 具体的数字和取舍过程，比「熟悉 UE5」这种描述有用得多。

### 不要写成流水账

反例：

> 今天做了武器系统，有点难，明天继续。

正例：

> 把射击逻辑从 `BP_Player` 抽成了 `BP_WeaponComponent`。
> 抽的时候发现原来射速是靠 `Delay` 节点递归调用的，改成 Timer 之后
> 切枪时旧 Timer 没清掉，导致切回来射速翻倍——原因找到了，见下。

区别在于：**后者记的是判断和原因，前者记的是时间**。时间不用记，git 提交历史里有。
